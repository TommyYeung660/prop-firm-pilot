## A. 學術與研究來源

### `A1` — Backtest Overfitting

- **來源**: David H. Bailey, Jonathan Borwein, Marcos Lopez de Prado, Qiji Jim Zhu, *The Probability of Backtest Overfitting*
- **連結**: https://papers.ssrn.com/sol3/papers.cfm?abstract_id=2326253
- **為何重要**:
  - 說明當策略研發包含大量參數搜尋、模型嘗試、樣本切分與篩選時，表面上漂亮的回測績效很容易只是過擬合。
- **本報告用法**:
  - 支持 `Research / Validation 嚴謹性` 必須把 walk-forward、ablation、selection-bias control 當成 release gate。
- **證據屬性**:
  - `風險提示`
- **限制**:
  - 不是針對 FX intraday 或 LLM 系統，但對任何高自由度策略研究都直接適用。

### `A2` — Deflated Sharpe Ratio

- **來源**: David H. Bailey, Marcos Lopez de Prado, *The Deflated Sharpe Ratio: Correcting for Selection Bias, Backtest Overfitting and Non-Normality*
- **連結**: https://papers.ssrn.com/sol3/papers.cfm?abstract_id=2460551
- **為何重要**:
  - 說明單看 Sharpe Ratio 容易高估策略可信度，尤其在多次試驗、厚尾分布、樣本不長時。
- **本報告用法**:
  - 支持本系統不能用少量回測或少數 prod run 就宣稱長期盈利可信度。
- **證據屬性**:
  - `風險提示`
- **限制**:
  - 它是評估框架，不替任何系統提供正面 alpha 證明。

### `A3` — Adaptive Markets / Regime Change

- **來源**: Andrew W. Lo, *Adaptive Markets and the New World Order*
- **連結**: https://papers.ssrn.com/sol3/papers.cfm?abstract_id=2508298
- **為何重要**:
  - 核心觀點是市場行為會隨參與者、制度、流動性與壓力環境改變，alpha 不是固定不變。
- **本報告用法**:
  - 支持本系統需要 `Learning / Adaptation`，但同時提醒「自適應」若沒有品質控管，也可能只是追噪音。
- **證據屬性**:
  - `事實支持 + 風險提示`
- **限制**:
  - 提供的是理論框架，不等於任何 adaptive system 都能盈利。

### `A4` — Machine Learning in Asset Pricing

- **來源**: Shihao Gu, Bryan Kelly, Dacheng Xiu, *Empirical Asset Pricing via Machine Learning*
- **連結**: https://academic.oup.com/rfs/article/33/5/2223/5758276
- **為何重要**:
  - 說明機器學習在大規模資產定價問題上可以提取非線性訊號，但需要嚴格樣本外驗證與穩健研究流程。
- **本報告用法**:
  - 支持 `qlib_market_scanner` 這種 ML ranking engine 在方向上合理。
  - 也支持「模型能找出訊號」不等於「production system 已可長期盈利」。
- **證據屬性**:
  - `啟發性證據`
- **限制**:
  - 主要研究背景不是零售 FX intraday；不能直接外推到本系統的 horizon。

### `A5` — Optimal Execution / Implementation Shortfall

- **來源**: Robert Almgren, Neil Chriss, *Optimal Execution of Portfolio Transactions*
- **連結**: https://www.math.nyu.edu/faculty/chriss/optliq_f.pdf
- **為何重要**:
  - 說明理論 alpha 必須經過交易成本、滑點、成交風險的折損；執行品質本身就是策略的一部分。
- **本報告用法**:
  - 支持 `Execution 可實現性` 不能只看方向判斷，還要看 latency、slippage、broker constraints、write budget。
- **證據屬性**:
  - `事實支持`
- **限制**:
  - 原文偏機構執行與最佳化框架，但對「implementation shortfall 是真實邊界」的結論完全適用。

### `A6` — Portfolio Construction

- **來源**: Harry Markowitz, *Portfolio Selection*
- **連結**: https://www.jstor.org/stable/2975974
- **為何重要**:
  - 長期盈利不是單筆交易正確率的同義詞，還取決於組合層級的分散化與風險配置。
- **本報告用法**:
  - 支持本系統若缺少 exposure budget、相關性控制、capital allocation，就不能被視為成熟長期系統。
- **證據屬性**:
  - `事實支持`
- **限制**:
  - 是經典組合理論，不直接提供 intraday FX 的實務細節。

## B. 開源平台與官方文件

### `O1` — Microsoft Qlib

- **來源**: Microsoft Qlib 官方 GitHub / 官方介紹頁
- **連結**:
  - https://github.com/microsoft/qlib
  - https://www.microsoft.com/en-us/research/project/qlib/
- **為何重要**:
  - Qlib 展示了成熟量化研究平台應具備的資料處理、模型工作流、回測與 online serving 能力。
- **本報告用法**:
  - 作為 `qlib_market_scanner` 的成熟度對照基線。
- **證據屬性**:
  - `事實支持`
- **限制**:
  - 平台能力不是盈利證據；真正關鍵仍是資料、標籤、研究流程與執行落地。

### `O2` — QuantConnect LEAN

- **來源**: LEAN 官方 GitHub / QuantConnect 官方文件
- **連結**:
  - https://github.com/QuantConnect/Lean
  - https://www.quantconnect.com/docs
- **為何重要**:
  - LEAN 展示了 research, backtest, live trading 共用一套 engine 與資料契約的成熟做法。
- **本報告用法**:
  - 對照本系統目前還缺哪些 research-to-live consistency gate。
- **證據屬性**:
  - `事實支持`
- **限制**:
  - 平台強不代表策略一定賺錢；它只是基礎設施範例。

### `O3` — Freqtrade

- **來源**: Freqtrade 官方文件
- **連結**:
  - https://www.freqtrade.io/en/stable/
  - https://www.freqtrade.io/en/stable/backtesting/
  - https://www.freqtrade.io/en/stable/hyperopt/
  - https://www.freqtrade.io/en/stable/plugins/#protections
- **為何重要**:
  - Freqtrade 在零售自動交易領域，把 backtesting、hyperopt、protections、dry-run / live run 做成清楚的操作面。
- **本報告用法**:
  - 對照本系統的保護機制、研究流程、live gating 還缺哪些可操作化能力。
- **證據屬性**:
  - `事實支持`
- **限制**:
  - 仍然不是盈利證據；只是顯示成熟 bot 通常怎麼做保護與驗證。

### `O4` — FinRL

- **來源**: FinRL 官方文件 / GitHub
- **連結**:
  - https://finrl.readthedocs.io/en/latest/
  - https://github.com/AI4Finance-Foundation/FinRL
- **為何重要**:
  - FinRL 是 ML / RL 交易研究框架代表，說明研究平台通常會把資料、環境、agent、benchmark 分開處理。
- **本報告用法**:
  - 用來對照本系統若要走更深的 adaptive / learning 路線，需要哪些嚴格的 benchmark 與 environment control。
- **證據屬性**:
  - `啟發性證據`
- **限制**:
  - RL 研究框架常有 simulation-to-live gap；不能直接當 production 盈利證明。

### `O5` — TradingAgents

- **來源**: TradingAgents arXiv / 官方 README
- **連結**:
  - https://arxiv.org/abs/2412.20138
  - https://github.com/TauricResearch/TradingAgents
- **為何重要**:
  - 這是本系統實際依賴的 LLM multi-agent 決策框架，也明確標示為研究用途。
- **本報告用法**:
  - 支持 `TradingAgents` 比較適合被定位成 research overlay，而非已證明穩定盈利的 execution brain。
- **證據屬性**:
  - `事實支持 + 風險提示`
- **限制**:
  - README 已明講表現受模型、溫度、交易週期、資料品質與非確定性因素影響。

## C. 本報告如何使用這些來源

| 維度 | 主要來源 | 用法 |
|---|---|---|
| Alpha 可得性 | `A4`, `O1`, `O4` | 支持 ML / ranking 方向合理，但不替本系統證明 alpha 已成立 |
| Execution 可實現性 | `A5`, `O2`, `O3` | 支持成本、滑點、live consistency 需納入正式 gate |
| Risk / Portfolio 可控性 | `A6`, `O2`, `O3` | 支持 portfolio-level control 是必要條件，不是加分項 |
| Learning / Adaptation 可持續性 | `A3`, `O4`, `O5` | 支持 adaptive 架構有意義，但也提醒噪音與漂移風險 |
| Research / Validation 嚴謹性 | `A1`, `A2`, `O1`, `O2`, `O3` | 支持本系統不能靠少量回測與少量 prod run 下強結論 |

---

## D. 來源使用上的保守原則

- 不把任何開源平台當成「可長期盈利」的證明。
- 不把任何單篇論文當成「本系統一定能複製」的證明。
- 只要來源與本系統市場型態不完全一致，就只用來建立判準或風險邊界。
- 對本系統是否能長期盈利，最終仍以本地三倉庫實作與後續 validation gate 為主。
