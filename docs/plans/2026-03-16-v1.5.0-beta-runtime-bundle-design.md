# v1.5.0_beta Runtime Bundle Repair Design

> **Date:** `2026-03-16`
> **Status:** Approved
> **Scope:** `qlib_market_scanner` + `prop-firm-pilot`

## Goal

讓既有 prod 啟動方式：

```bash
uv run python -m src.main --config config/e8_one_5k_challenge.yaml --scheduler
```

可以在 `v1.5.0_beta` 正常運行，而不需要操作員改命令或手動準備 scanner sidecars。

## Root Cause

`prop-firm-pilot` 在 `v1.5.0_beta` 對 scanner bundle 啟用了嚴格 contract gate：

- 需要 `manifest.json`
- 需要 `metrics.json.validation.status` 為 passing
- 需要 `schema_versions` / `research_run_id`

但 `qlib_market_scanner` 的一般 runtime 路徑只會輸出：

- `outputs/signals/signals.csv`
- `outputs/metrics/metrics.json`

它不會直接產出 live manifest，也不會把 metrics validation 寫成 passing。因此 `ScannerBridge` 會：

1. 先讀到本次 run 的 `outputs/signals/signals.csv`
2. 再 fallback 去找 `data/shared_export/manifest.json`
3. 若 shared export 是舊檔或舊格式，就報 `manifest missing schema_versions`

所以真正問題不是 scanner 沒跑，而是 **upstream runtime output 與 downstream live contract 沒有收斂成同一個 bundle family**。

## Chosen Approach

採用 **Upstream-Owned Strict Runtime Bundle**：

1. `qlib_market_scanner` 一般 runtime 每次成功跑完後，都要生成同 run 的 live bundle sidecars：
   - `outputs/manifest.json`
   - validated `outputs/metrics/metrics.json`

2. `prop-firm-pilot` 在 ingest `outputs/signals/signals.csv` 時，只能配對：
   - `outputs/manifest.json`
   - `outputs/metrics/metrics.json`

3. `data/shared_export` 與 `outputs` 必須視為兩個不同 bundle family，不允許跨 family 配對 sidecars。

## Design Decisions

### 1. 不放寬 pilot gate

不接受「manifest 不存在時改信任裸 `signals.csv`」這種方案。原因是這會直接削弱 `v1.5.0_beta` 這次新增的 contract gate。

### 2. Contract 由 upstream 擁有

`qlib_market_scanner` 既然是 bundle producer，就應該在 runtime 直接產生完整可 ingest 的 live bundle，而不是把 schema 組裝責任推給 `prop-firm-pilot`。

### 3. Shared export 與 runtime outputs 分流

`data/shared_export` 可以繼續服務其他 consumer，但不能再污染 live scanner ingest。`ScannerBridge` 必須按 signals 路徑選擇同一個 family 的 manifest / metrics。

### 4. Fail closed

若 runtime bundle sidecar 生成失敗，scanner run 應視為 contract failure，而不是默默讓 pilot 用裸 CSV 進場。

## Expected Outcome

修復後，同一條 scheduler 命令應表現為：

- scanner subprocess 成功
- `outputs/signals/signals.csv` 正常生成
- `outputs/manifest.json` 正常生成
- `outputs/metrics/metrics.json.validation.status == "passed"`
- `ScannerBridge` 不再誤吃舊 `data/shared_export/manifest.json`
- pilot 不再出現 `manifest missing schema_versions`

## Non-Goals

- 不修改 prod 操作命令
- 不在這次修復中重做 FX cadence 選型
- 不用 fallback 模式繞過 contract gate
