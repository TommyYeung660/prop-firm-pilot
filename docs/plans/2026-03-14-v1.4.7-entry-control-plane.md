# v1.4.7 Tactical Entry Control Plane Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 將 tactical entry 升級為可回放、可校準、可運維的 entry control plane，讓每次 entry verdict 都有 deterministic reason taxonomy、固定 lifecycle resolution、完整 provenance，以及每日 calibration snapshot。

**Architecture:** 以 `src/decision/tactical_validator.py` 的 verdict schema 為中心，讓 scheduler 只消費標準化 `resolution` 語義來驅動 `claimed / tactical_pending / ready_for_exec / timed_out / cancelled` 轉移。完整 verdict bundle 寫入 trade journal，operational metrics 追蹤 tactical friction，最後由獨立 aggregation module 產生每日 entry calibration snapshot。

**Tech Stack:** Python 3.10, `dataclasses`, Pydantic v2 models already in repo, `loguru`, async `Scheduler`, JSONL `TradeJournal`, `pytest`

```python
@dataclass
class GateResult:
    gate_name: str
    passed: bool
    status: Literal["PASS", "FAIL", "SOFT_FAIL", "DEGRADED", "SKIPPED"] = "PASS"
    reason_code: str = ""
    observed_value: float | None = None
    threshold_value: str = ""
    detail: str = ""


@dataclass
class TacticalResult:
    action: Literal["PASS", "WAIT", "REJECT"]
    resolution: Literal[
        "EXECUTE_NOW",
        "RETRY_PENDING",
        "EXECUTE_DEGRADED",
        "SKIP_CANCEL",
        "EXPIRE_TIMEOUT",
    ]
    summary_reason_code: str = ""
    policy_hints: dict[str, Any] = field(default_factory=dict)
    provenance: dict[str, Any] = field(default_factory=dict)
```

Add small helper methods so the validator maps gate failures to fixed reason codes instead of ad-hoc `detail` strings. Keep the first cut journal-first and do not add DB migrations in this task.
