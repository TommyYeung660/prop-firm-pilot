# v1.4.5 Tactical Exit Design

**Version Target:** `v1.4.5`

**Goal:** Upgrade the tactical layer from entry-only timing validation into a unified entry+exit subsystem that manages dynamic exits using WebSocket-first market data, regime-aware stop/target logic, and a single partial-close action.

**Scope:** `prop-firm-pilot` primary implementation, with existing `TradingAgents` re-evaluation retained only as an exception path.

---

## 1. Problem Statement

`v1.4.2` already has:

- WebSocket-first quote and bar ingestion through `MarketDataHub`
- entry-side tactical validation through `TacticalValidator`
- a simple breakeven stop path in `Scheduler._apply_breakeven_stops()`
- LLM-based position re-evaluation in `Scheduler._reevaluate_open_positions()`

However, exit control is fragmented:

- price-driven protection is isolated in a single breakeven helper
- strategic/semantic exit is isolated in a separate LLM re-evaluation path
- there is no unified state model for dynamic stop loss, take profit repricing, or partial profit taking
- there is no broker write throttling policy specialized for dynamic exit management

This produces a structural mismatch:

- entry timing is tactical and systematic
- exit timing is partially tactical, partially ad hoc

For `v1.4.5`, exits should become an explicit tactical responsibility.

---

## 2. Design Goals

### 2.1 Functional Goals

- Monitor all open positions on a minute cadence using WebSocket-first data
- Convert exit decisions into a deterministic tactical rule engine
- Support dynamic stop tightening, take-profit repricing, and one-time partial close
- Preserve strong trends while protecting open profit during weakening conditions
- Keep LLM re-evaluation available for exceptional situations only

### 2.2 Risk Goals

- Never widen stop loss
- Prevent excessive broker writes
- Avoid fixed take-profit truncation of strong trend trades
- Reduce giveback during momentum weakening or volatility regime deterioration
- Keep dynamic exit compatible with prop-firm drawdown constraints

### 2.3 Engineering Goals

- Avoid growing `Scheduler` into a monolithic exit orchestrator
- Reuse the existing tactical indicators and market-data hub
- Persist exit decisions and modified levels for postmortem and reflection
- Add tests before any production implementation changes

---

## 3. Non-Goals

- No reinforcement learning or online optimizer in `v1.4.5`
- No full portfolio-level correlation guard in `v1.4.5`
- No replacement of broker execution REST paths
- No removal of LLM re-evaluation from the codebase; only a downgrade from primary to exception path
- No multi-stage partial-close ladder; `v1.4.5` supports one partial close only

---

## 4. Research Summary

This design is based on a combination of codebase constraints and external evidence.

### 4.1 Stop-loss rules only add value under forecastable structure

Kaminski and Lo show that stop-loss rules reduce expected returns under random-walk dynamics, but can add value under momentum or regime-switching processes and can reduce variance when they switch exposure into a lower-volatility state.  
Source: Kaminski & Lo, "When do stop-loss rules stop losses?" Journal of Financial Markets (2014).  
Link: https://www.sciencedirect.com/science/article/pii/S138641811300030X

**Design implication:** dynamic exits must be regime-aware, not blindly static or always-on.

### 4.2 Trend persistence justifies letting winners run

Moskowitz, Ooi, and Pedersen document persistent time-series momentum across futures and currencies, with continuation lasting up to about a year before longer-horizon partial reversal.  
Source: "Time Series Momentum" (2010).  
Link: https://elmwealth.com/wp-content/uploads/2017/06/timeseriesmomentum.pdf

**Design implication:** fixed take-profit alone is structurally too blunt; strong continuation regimes need `TP extension + tighter trailing SL`.

### 4.3 Volatility regimes should change risk-taking

Moreira and Muir show that taking less risk when volatility is high improves Sharpe ratios because volatility changes are not fully offset by changes in expected return.  
Source: "Volatility Managed Portfolios" NBER Working Paper 22208 / Journal of Finance (2017).  
Link: https://www.nber.org/papers/w22208

**Design implication:** when ATR regime worsens, the system should reduce risk by tightening stops, contracting targets, or partially de-risking.

### 4.4 Selling winners too early is a real behavioral failure mode

Odean documents the disposition effect: investors hold losers too long and sell winners too soon, harming performance.  
Source: Odean, "Are Investors Reluctant to Realize Their Losses?" Journal of Finance (1998).  
Link: https://faculty.haas.berkeley.edu/odean/papers%20current%20versions/areinvestorsreluctant.pdf

**Design implication:** partial close must be conditional and once-only, not a blanket “take profit early” reflex.

### 4.5 Rule-based stop/take-profit logic is computationally tractable

Zakamouline describes a computational framework for evaluating stop-loss, take-profit, and trailing-stop strategies.  
Source: "A simple computational model for analyzing the properties of stop-loss, take-profit, and price breakout trading strategies" Computers & Operations Research (2004).  
Link: https://www.sciencedirect.com/science/article/pii/S0305054804001194

**Design implication:** a deterministic state machine is the right first implementation path before any heavier optimizer.

### 4.6 Design inference

The specific `v1.4.5` combination:

- early breakeven
- ATR-based trailing stop
- dual-mode take-profit repricing
- one-time 50% partial close under weakening

is an implementation inference from the above evidence and from this repo’s current structure. It is not copied from a single source.

## 5. Proposed Architecture

### 5.1 High-Level Structure

Keep entry tactical logic intact and add a new exit tactical subsystem:

- `src/decision/tactical_validator.py`
  Entry-only validator remains responsible for `PASS / WAIT / REJECT` before execution.

- `src/decision/tactical_exit_manager.py`
  New exit tactical orchestrator. Consumes open-position state, execution metadata, and market data. Produces one exit action per evaluation cycle.

- `src/decision/tactical_exit_rules.py`
  New pure rule engine / indicator helpers for exit state classification and level calculation.

- `src/scheduler/scheduler.py`
  Position monitor loop delegates exit evaluation and execution to the new subsystem instead of directly calling `_apply_breakeven_stops()` for the primary path.

### 5.2 Why a Separate Exit Manager

Do not overload `TacticalValidator` with lifecycle orchestration.

Entry tactical and exit tactical share indicators and market data, but they solve different problems:

- entry tactical decides when to open
- exit tactical decides how to protect, extend, reduce, or close existing risk

Keeping them separate preserves clarity and testability.

---

## 6. Exit Tactical State Machine

Each open position is evaluated into one of four internal states:

1. `INITIAL_RISK`
   Position is live under original `SL/TP`, with no profit-protection action yet applied.

2. `PROTECTION`
   Position has reached the early protection threshold and should move to breakeven or better.

3. `TREND_EXTENSION`
   Trend remains healthy; use tighter trailing stop and optionally extend TP.

4. `PROFIT_PROTECTION`
   Position is still profitable, but tactical conditions have weakened; prioritize partial de-risking and tighter profit capture.

These internal states map to external actions:

- `HOLD`
- `MOVE_TO_BREAKEVEN`
- `TRAIL_SL`
- `REPRICE_TP`
- `PARTIAL_CLOSE`
- `EXIT_NOW`

Only one action may be emitted per position per evaluation cycle.

## 8. Core Algorithm

### 8.1 Evaluation Frequency

- Default evaluation cadence: every `60s`
- Use WebSocket-first quote and closed-bar data
- Do not issue broker writes every minute unless thresholds justify it

### 8.2 Action Priority

The exit manager evaluates actions in this strict order:

1. `EXIT_NOW`
2. `PARTIAL_CLOSE`
3. `TRAIL_SL`
4. `MOVE_TO_BREAKEVEN`
5. `REPRICE_TP`
6. `HOLD`

This ordering prevents contradictory write actions in the same cycle.

### 8.3 Early Protection

Preserve the existing early-protection logic as the minimum safety layer:

- trigger at approximately `0.3R` profit by default
- move `SL` to entry price if it improves risk

This becomes part of the new tactical exit manager, not a standalone scheduler helper.

### 8.4 Trend-Extension Mode

Conditions:

- ATR regime is normal, not extreme
- `EMA(8)` stays aligned with position direction versus `EMA(21)`
- `RSI` is not in a strong adverse extreme
- latest candle quality does not suggest structural deterioration

Actions:

- tighten `SL` via ATR trailing floor
- optionally extend `TP` if extension exceeds configured minimum delta
- never partial close in this mode

Recommended first implementation:

- For `BUY`: `trailing_floor = recent_high - atr_multiplier * ATR_1h`
- For `SELL`: `trailing_floor = recent_low + atr_multiplier * ATR_1h`
- The exact anchor may use recent `5m` structure or `1h` swing depending on available clean data

### 8.5 Profit-Protection Mode

Conditions:

- position already has meaningful floating profit
- tactical momentum weakens
- or ATR regime worsens
- or price structure degrades while not yet proving a full reversal

Actions:

- if no prior partial close: `PARTIAL_CLOSE 50%`
- after partial close, prefer tighter `TRAIL_SL`
- if weakness persists, contract `TP`

### 8.6 Dual-Mode Take-Profit Repricing

`TP` can move in both directions, but only under controlled rules.

#### Extension

Allowed when:

- trend-extension conditions hold
- current position is not already in profit-protection mode
- new TP materially improves expected payoff

#### Contraction

Allowed when:

- weakening conditions are present
- partial close has occurred or tightening logic has already activated
- target contraction does not collapse into noise-level distance

### 8.7 Exit-Now Conditions

`EXIT_NOW` is reserved for clear adverse structure:

- strong directional contradiction in tactical indicators
- severe volatility regime break
- market-event escalation with tactical conflict
- optional future integration with portfolio/correlation guard

`EXIT_NOW` is deterministic in `v1.4.5`. LLM re-evaluation is not required for normal tactical closes.

## 9. Broker Write Controls

This is safety-critical for operational stability.

### 9.1 Hard Rules

- Stop loss may only tighten; never widen
- Partial close may happen only once per position
- Any partial close must preserve broker `min_lot` and `volume_step`
- Each evaluation cycle may emit at most one broker-mutating action per position

### 9.2 Throttles

- per-position modify cooldown
- per-position TP reprice cooldown
- minimum stop improvement delta
- minimum TP improvement delta
- optional per-position max write count for lifetime of trade

### 9.3 Budget Awareness

Before mutating actions, consult MatchTrader write budget:

- if daily write budget is tight, prefer `HOLD` unless the action is materially protective
- reserve emergency capacity for compliance closes and forced exits

This is necessary because WebSocket data is high-frequency, but broker writes are still rate-limited REST operations.

---

## 10. LLM Re-Evaluation Redesign

Current `Scheduler._reevaluate_open_positions()` remains in place, but changes role.

### 10.1 New Role

LLM re-evaluation becomes an exception path only:

- triggered when tactical signals materially conflict
- triggered when market-event context is high impact
- triggered when severe regime shift suggests semantic reassessment

### 10.2 Normal Case

Normal open-position management is handled by tactical exit alone.

This reduces:

- latency
- cost
- nondeterminism

while preserving the ability to escalate unusual cases.

The existing `tactical` config should grow an `exit` block rather than overloading `scheduler`.

```yaml

  exit:
    enabled: true
    evaluation_interval_seconds: 60
    breakeven_activation_r: 0.3
    atr_trailing_multiplier: 2.5
    trend_extension_tp_atr_multiplier: 1.5

    partial_close_ratio: 0.5
    partial_close_min_r: 0.8
    modify_cooldown_seconds: 300

    min_tp_improvement_pips: 3.0

```

Key principle:

- entry tactical config stays entry-focused
- exit tactical config remains separate but adjacent

## 13. Integration Plan

### 13.1 Scheduler Integration

Replace the current direct call flow:

- `_apply_breakeven_stops()`
- `_reevaluate_open_positions()`

with:

1. collect open positions + opened intents
2. run tactical exit evaluation for each position
3. execute at most one action per position
4. optionally escalate to LLM re-evaluation only for exception cases

### 13.2 Backward Compatibility

Keep existing helpers temporarily during migration:

- `_apply_breakeven_stops()` may be retained internally or wrapped until tests fully migrate
- `_reevaluate_open_positions()` remains callable, but not on the hot path for every position every cycle

### 14.1 Pure Rule Tests

New tests for:

- trend-extension vs profit-protection mode
- ATR trailing floor calculation
- TP extension conditions
- TP contraction conditions
- single partial-close eligibility
- `SL` never widens

### 14.2 Scheduler / Orchestration Tests

New tests for:

- position monitor delegates to tactical exit manager
- only one action executes per position per cycle
- cooldown blocks repeated broker edits
- low broker write budget suppresses non-critical actions
- exception path triggers LLM re-evaluation only under configured conditions

### 14.3 Broker Mutation Tests

New tests for:

- partial close volume obeys `min_lot` and step
- `modify_position()` carries forward untouched fields correctly
- verification failures do not mark action as complete
- execution metadata updates after tactical exit actions

### 14.4 Regression Tests

Existing tests to preserve:

- breakeven verification behavior

- position monitor close handling
- tactical entry validation behavior

## 15. Rollout Strategy

`v1.4.5` should ship in phases:

1. Introduce tactical exit rule engine and pure tests
2. Add `HOLD / MOVE_TO_BREAKEVEN / TRAIL_SL` path
3. Add `REPRICE_TP`
4. Add single `PARTIAL_CLOSE 50%`
5. Relegate LLM re-evaluation to exception path

This sequencing reduces operational risk and keeps failures easier to localize.

---

## 16. Risks and Mitigations

### Risk: Broker write churn

Mitigation:

- cooldowns
- minimum improvement deltas
- one action per cycle
- budget-aware suppression

### Risk: Dynamic TP causes overfitting or unstable behavior

Mitigation:

- deterministic bounded repricing
- no optimization loop in first release
- extensive rule tests and trade-journal telemetry

### Risk: Partial close damages expectancy if used too early

Mitigation:

- one-time only
- available only in profit-protection mode
- require minimum floating profit threshold

### Risk: Tactical exit conflicts with compliance protection

Mitigation:

- compliance remains the outermost guard
- tactical exit can tighten or close, never weaken risk controls

---

## 17. Final Recommendation

Implement `v1.4.5` as a deterministic, regime-aware tactical exit subsystem with:

- early breakeven as a minimum protection layer
- ATR-based trailing stop for healthy trends
- dual-mode take-profit repricing
- a single 50% partial close during weakening conditions
- LLM re-evaluation retained only for exceptional escalation

This is the strongest design fit for the current repo because it:

- uses the existing WebSocket-first data plane
- reduces fragmentation in exit logic
- preserves winners better than fixed TP
- protects profit more systematically than the current breakeven-only path
- remains testable and operationally controllable
