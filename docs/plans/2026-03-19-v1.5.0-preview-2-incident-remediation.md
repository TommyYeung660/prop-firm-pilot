# v1.5.0 Preview 2 Incident Remediation Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 修正 `1.5.0_preview` 在 `2026-03-18` 到 `2026-03-19` prod 視窗暴露出的 stale market data / unsafe tactical degrade / attribution drift 問題，並將版本提升到 `1.5.0_preview_2`。

**Architecture:** 交易鏈仍維持 `scanner -> tradingagents -> tactical gate`，但 market-data 健康度改成 scanner admission 與 tactical expiry 的共同硬前提。只有明確屬於短暫 warmup 的缺口才允許 retry；任何 stale quote、stale 5m/1h bars、或 UTC rollover 後仍停留在前一交易日的資料，都必須 fail closed。關單與日報層則同時保留 `trigger_source` 與 `final_close_reason`，讓 prod bundle 可以正確區分 tactical exit、degrade-to-exec、以及單純 TP/SL 結果。

**Tech Stack:** Python 3.10, asyncio, Pydantic, pytest, uv, JSONL trade journal, Markdown.

**Step 3: Implement the minimal policy fix**

在 `src/decision/tactical_validator.py` 為資料不足型 `WAIT` 加上 policy hint：

```python
policy_hints={"degrade_allowed": False, "failure_family": "market_data"}
```

在 `src/scheduler/scheduler.py` 的 `_retry_tactical_pending()` 加 helper：

```python
def _tactical_wait_allows_degrade(result: TacticalResult) -> bool:
    if result.policy_hints.get("degrade_allowed") is False:
        return False
    blocked_prefixes = (
        "market_data.",
        "data.reject.",
        "freshness.fail.",
        "atr.fail.insufficient_1h_data",
    )
    codes = [result.summary_reason_code, *failed_hard_gate_codes]
    return not any(code.startswith(prefix) for code in codes for prefix in blocked_prefixes)
```

只有 helper 回傳 `True` 時才走 degrade；否則走 `_timeout_intent_safe(..., context="tactical_retry_expired_market_data")`。
