# v1.4.6d Prod Log Fixes Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Fix the three production issues seen in `prod_logs_20260314_v1.4.6d/`: closed-market position monitoring still consuming tactical/LLM resources, tactical exits failing to persist because of broker price precision mismatch, and missing defensive exits for clearly failed initial-risk positions.

**Architecture:** This implementation keeps the existing scheduler + tactical-exit split. `Scheduler` gains a closed-market hard gate for position monitoring, the tactical rule engine gains one conservative deterministic defensive-loss exit, and MatchTrader precision handling is normalized on both write and verify paths so successful broker updates are no longer treated as failures.

**Tech Stack:** Python 3.10, asyncio, pytest, pandas, Pydantic v2, loguru, MatchTrader REST client

In `src/decision/tactical_exit_rules.py`, add a helper and wire it before the normal `HOLD` path:

```python
def _should_defensive_exit_initial_risk(
    snapshot: TacticalExitSnapshot,
    context: ExitSignalContext,
    config: TacticalExitConfig,
) -> bool:
    if snapshot.unrealized_r > config.defensive_exit_loss_r:
        return False
    if context.ema_aligned is not False:
        return False
    if not context.adverse_rsi:
        return False
    if config.defensive_exit_require_strong_candle:
        return context.opposing_candle_strong
    return context.opposing_candle
```

Then in `choose_tactical_exit()`:

```python
if state == "INITIAL_RISK" and _should_defensive_exit_initial_risk(snapshot, context, config):
    return TacticalExitDecision(
        action="EXIT_NOW",
        state=state,
        reason="initial_risk_structure_failure",
    )
```
