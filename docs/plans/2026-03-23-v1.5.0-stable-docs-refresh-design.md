# v1.5.0 Stable 文檔更新設計

## 背景

`prop-firm-pilot` 主線已從 `v1.5.0_preview_2` 的修復與驗證階段，進一步收斂到 `v1.5.0_stable` 的實作基線。現有 [docs/PropFirmPilot_v1.5.0_road_map.md](/C:/Users/tommy.yeung/CursorProjects/prop-firm/prop-firm-pilot/docs/PropFirmPilot_v1.5.0_road_map.md) 仍保留大量 preview 時代敘事，尚未完整反映目前 `main` 的 stable runtime 邊界；同時 repo 內也缺少一份面向 operator + 技術讀者的 stable 系統解說文件。

本次工作要更新 roadmap，並新增一份 stable report，讓讀者可以同時回答兩個問題：

1. `v1.5.0_stable` 現在主線已經落地什麼、還差什麼。
2. 一筆交易從 scanner 開始，到 execution、持倉管理、平倉與紀錄，整條鏈路如何運作。

## 目標

1. 將 roadmap 從 preview 滾動規劃，改寫為 `v1.5.0_stable` 的主線入口文件。
2. 新增 stable report，完整說明系統功能與交易生命週期。
3. 明確寫出 `TradingAgents` / LLM decision 在 stable 預設為關閉。
4. scanner 章節以 `qlib_market_scanner` 的中文 roadmap 風格來描述其 contract 與上下游邊界，而不是用 alpha 宣傳語氣。

## 非目標

1. 不在這次工作中變更任何 runtime 行為。
2. 不重寫舊版歷史設計稿，只更新目前對外主要入口文檔。
3. 不把 changelog、runbook、incident review 內容重新搬進 stable report。

## 核心敘事原則

### 1. Roadmap 寫版本邊界，Stable Report 寫系統流程

- roadmap 只講 stable 現況、缺口與後續波段
- stable report 才展開完整交易生命週期

### 2. Scanner 以 contract 視角描述

scanner 在這次文檔中被描述為：

- 上游 research / selection / signal export 系統
- 對 downstream 提供 versioned bundle、target-date、side-aware signals、metadata
- 交易鏈的起點，而不是單獨包辦風控、執行與持倉管理

### 3. TradingAgents default-off 是 stable 安全預設

必須明寫：

- `TRADINGAGENTS_ENABLED` 未設或為 `false` 時，`agents.enabled = false`
- `entry_funnel_mode` 會從 `scanner_llm_tactical` 自動降級成 `scanner_tactical`
- tactical exit 的 `use_llm_exception_path` 被強制關閉
- position re-evaluation 不啟動
- stable 預設實際路徑為 `scanner -> tactical -> execution`

### 4. 不混寫 preview 歷史與 stable 現況

- preview 僅作為 stable baseline 的來源背景
- 主要敘事一律以目前 `main` 的 stable 實作為主
