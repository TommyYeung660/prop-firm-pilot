# v1.5.0 Preview Incident Remediation Design Update

**Date:** `2026-03-18`

## Decision Record

本輪 remediation 的設計結論已固定如下：

- `Best Day Rule` 新單 gate 只看 actual `daily_pnl`，不再看 hypothetical TP profit。
- deterministic compliance headroom 在 scheduler admission 先檢查，避免 candidate / intent / tactical churn。
- market-data 改為 `broker quote-first + API bars-first + websocket auxiliary`。
- scanner success 需同時滿足 process success、artifact success、ingestion success、`target_date` matched。
- Telegram alerting 必須具備 retry accounting 與 secondary sink。

## Why This Design

### Best Day

本案最重要的 correctness boundary 是：沒有任何交易時，不得因 Best Day 被阻擋。這不是 risk appetite 調整，而是語義修正。actual daily PnL 與 hypothetical TP potential profit 必須完全分離。

### Market Data

incident bundle 顯示 websocket 在該視窗內反覆退化，但 `EODHD LIVE API` 又只有 delayed 1 minute，因此不能用單一來源硬替代。最穩定的主路徑是：

- broker quote for live tradable quote / spread
- API bars for closed bar history
- websocket only for auxiliary telemetry and non-primary fallback

### Scanner Success Contract

operator 真正需要的是「這次 scan 是否產生可交易、可落盤、且 target date 正確的 signals」，不是單純 subprocess 是否 exit `0`。因此 success 判定必須推遲到 bundle ingestion 後。

### Alerting

incident 期間若 primary Telegram channel timeout，而系統沒有 retry 與 secondary sink，則 operator 會同時失去告警與現場診斷。secondary sink 先落到 `TradeJournal`，保證 incident 後可重建。

## Implemented Component Changes

### Compliance / Execution

- `PropFirmGuard.check_best_day_rule()` 改為 actual-daily-PnL-only
- execution-side Best Day reason wording 對齊 actual daily PnL semantics
- `check_admission_headroom()` 新增 scheduler admission guard path

### Tactical / Scheduler

- tactical result 新增 `failed_hard_gate_names`
- tactical result 新增 `failed_hard_gate_reason_codes`
- tactical result 新增 `hard_gate_reason_codes`
- calibration snapshot 新增 hard-gate aggregation

### Market Data

- `MarketDataHub.get_quote()` 改為 broker primary
- `MarketDataHub.get_bars()` 改為 API warm/cache primary、websocket fallback
- `feed_status()` 顯式暴露 routing 與 degraded summary
- `get_entry_readiness()` 改為 primary-path-based block semantics

### Scanner

- `ScannerBridge.run_pipeline()` 改為 stage-based outcome logging
- `target_date` 缺失時只記 `pipeline incomplete`，不記 success

### Alerts

- `AlertService.send()` 新增 retry loop
- retry 會記錄 Telegram retry metrics
- primary 失敗後可走 secondary sink
- circuit open 且 probe 尚未到期時，secondary sink 仍可接手
- scheduler mode 與 daily-cycle mode 均將 secondary sink 接到 `TradeJournal` `ALERT_FALLBACK`

## Open Calibration Follow-Up

以下項目已被明確拆出與觀測，但尚未在本輪直接調 threshold：

- USDCAD `< 2.0x` spread hard limit 是否需 pair-specific calibration
- `atr.fail.insufficient_1h_data` 的暖機條件是否應調整 bar requirement 或 startup grace period

這兩項仍需下一輪 live evidence 再決定，不在本輪無證據下直接放寬 gate。
