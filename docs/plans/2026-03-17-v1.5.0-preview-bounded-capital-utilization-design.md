# v1.5.0 Preview Bounded Capital Utilization Design

**Date:** `2026-03-17`

**Goal:** 在不放寬 prop-firm safety guard、也不重寫完整 portfolio engine 的前提下，為 `prop-firm-pilot` 加入一個 bounded capital utilization uplift，讓倉位稀疏時可以更有紀律地使用既有風險預算。

## Context

目前系統已完成：

- `qlib_market_scanner` 的 `v1.5.0` cadence 決策、schema contract、validation gate
- `qlib_rd_agent -> qlib_market_scanner` 的 candidate/promoted factor contract
- `prop-firm-pilot v1.5.0_beta_2` 的 operational repair gate
- E8 One 5K 的 7-pair universe 擴充與 `scanner.topk=5`

但 execution sizing 仍是固定單筆 `default_risk_pct`，代表：

- 如果同時只有 1 筆高品質 setup，系統仍只會使用單筆預設風險
- 即使 `max_positions` 尚未用滿，也不會把既有名目風險預算重分配到較少的持倉
- `max_risk_pct` 雖已存在於 config，現行 runtime 並未使用

## Non-Goals

- 不做 base/quote currency exposure budget
- 不做 correlation-aware portfolio construction
- 不新增新的 scanner cadence 或更動 scanner contract
- 不放寬 compliance 的 daily / max drawdown / best-day safety margin
- 不把 uplift 擴張成 optimizer-driven risk engine

## Chosen Approach

採用「有限風險預算重分配」：

1. 將帳號的名目 entry risk budget 視為：
   - `portfolio_budget_pct = default_risk_pct * max_positions`
2. 當前若只有少量 open positions，新的 trade 可以分到較高的 slot budget：
   - `slot_budget_pct = portfolio_budget_pct / (open_positions + 1)`
3. 單筆風險仍必須受 `max_risk_pct` 上限約束：
   - `bounded_cap_pct = min(slot_budget_pct, max_risk_pct)`
4. uplift 不直接對所有信號開滿，而是由 scanner confidence 決定使用多少 uplift headroom：
   - `high` -> 用滿 bounded headroom
   - `medium` -> 用一半 bounded headroom
   - `low` / unknown -> 維持 `default_risk_pct`

最終：

- `effective_risk_pct = default_risk_pct + confidence_factor * (bounded_cap_pct - default_risk_pct)`

## Why This Approach

相較於直接提高 `default_risk_pct`：

- 它只在組合稀疏時提高單筆風險
- 一旦持倉數接近 `max_positions`，風險自然退回 `default_risk_pct`
- aggregate nominal budget 不超過原本 `default_risk_pct * max_positions` 的設計意圖

相較於直接做 exposure / correlation guard：

- 這版不需要先引入更大範圍的組合建模
- 改動面集中在 execution sizing
- 仍可利用 `scanner_confidence` 這個已穩定落地的上游 metadata

## Affected Components

### `src/execution/capital_allocator.py`

新增一個小型 helper，專責：

- 根據 `ExecutionConfig`、`open_positions`、`scanner_confidence`
- 計算 `effective_risk_pct`
- 回傳 audit-friendly 的 allocation decision

### `src/execution/position_sizer.py`

新增 risk override 能力：

- `calculate_volume(..., risk_pct_override=None)`
- 若有 override，使用 override；否則維持既有 `default_risk_pct`

### `src/execution/engine.py`

在 `_build_trade_plan()` 前決定 effective risk：

- 以 account snapshot 的 `open_positions` 計算 bounded allocation
- 使用 intent 的 `scanner_confidence`
- 把 effective risk pct 傳給 `PositionSizer`
- 將 `risk_pct` 與 allocation metadata 寫入 execution meta / debug log

## Safety Properties

- `ComplianceResult` 的 daily/max drawdown 與 best-day rule 不改
- 每筆風險永遠不超過 `max_risk_pct`
- 若 `max_risk_pct <= default_risk_pct`，uplift 自動失效，退回原行為
- 若 confidence 為 `low` 或無法識別，退回原行為

## Testing Strategy

1. `tests/test_capital_allocator.py`
   - 驗證 sparse portfolio 時 `high` confidence 會 uplift 到 bounded cap
   - 驗證 `medium` confidence 只用半個 uplift headroom
   - 驗證 `low` confidence 不 uplift
   - 驗證接近滿倉時自然退回 `default_risk_pct`

2. `tests/test_position_sizer.py`
   - 驗證 `risk_pct_override` 會影響 volume 計算
   - 驗證未傳 override 時保持舊行為

3. `tests/test_engine.py`
   - 驗證 execution path 會把有效 risk pct 傳給 sizer
   - 驗證 sparse + high confidence 使用 uplift
   - 驗證 fallback path 仍使用 default sizing

4. `tests/test_version.py`
   - 驗證版本 identity 已從 `1.5.0_beta_2` bump 到 `1.5.0_preview`
