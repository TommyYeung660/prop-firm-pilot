## Task 1: Consecutive Loss Circuit Breaker (P2.5)

**Problem:** No mechanism to stop opening new trades after consecutive stop-losses. On 2026-03-09, 3 consecutive EURUSD SELL trades hit SL in one session. The system should have paused after the 2nd loss.

**Root cause:** `_scanner_loop()` has no awareness of recent loss history. It creates new intents regardless of how many recent trades hit SL.

**Fix approach:**
1. Add `count_sl_hits_today()` and `count_symbol_losses_today()` query methods to `DecisionStore`.
2. Add config params: `daily_sl_hit_limit` (default=2), `symbol_loss_limit` (default=2) to `SchedulerConfig`.
3. Add circuit breaker gate in `_scanner_loop()` before intent creation: check daily SL hits and per-symbol losses.
4. Track in Scheduler with `_circuit_breaker_paused_today: str | None` similar to `_best_day_paused_today`.

**Files:**
- Modify: `src/decision_store/sqlite_store.py` (add `count_sl_hits_today`, `count_symbol_losses_today`)
- Modify: `src/config.py` (add `daily_sl_hit_limit`, `symbol_loss_limit` to `SchedulerConfig`)
- Modify: `src/scheduler/scheduler.py` (add circuit breaker checks in `_scanner_loop`)
- Test: `tests/test_circuit_breaker.py` (new file)

def count_sl_hits_today(self, trade_date: str) -> int:
    """Count closed intents with exit_reason='sl_hit' for a given trade date."""
    row = self._conn.execute(
        """SELECT COUNT(*) as cnt FROM intents
           WHERE trade_date = :td AND status = 'closed'
             AND exit_reason = 'sl_hit'""",
        {"td": trade_date},
    ).fetchone()
    return row["cnt"] if row else 0

def count_symbol_losses_today(self, symbol: str, trade_date: str) -> int:
    """Count closed intents with exit_reason='sl_hit' for a specific symbol+date."""
    row = self._conn.execute(
        """SELECT COUNT(*) as cnt FROM intents
           WHERE symbol = :symbol AND trade_date = :td
             AND status = 'closed' AND exit_reason = 'sl_hit'""",
        {"symbol": symbol, "td": trade_date},
    ).fetchone()
    return row["cnt"] if row else 0

## Task 2: Same-Symbol Same-Direction Duplicate Entry Limit (P2.6)

**Problem:** The system opened 3 EURUSD SELL trades in the same day. Even after the first SELL hit SL, it created another SELL intent for the same symbol in the same direction.

**Root cause:** `intent_exists()` only checks for *in-progress* intents (pending/claimed/etc). Once a trade closes, the scanner is free to create a new intent for the same symbol+direction immediately.

**Fix approach:**
1. Add `has_active_position_for_symbol()` query to `DecisionStore` — checks if there's currently an opened intent for this symbol.
2. Add `has_same_direction_today()` query to `DecisionStore` — checks if we already executed a trade in the same direction for this symbol today (regardless of outcome).
3. Add config params: `max_same_direction_per_day` (default=1), `same_symbol_cooldown_minutes` (default=60) to `SchedulerConfig`.
4. Add gates in `_scanner_loop()` before intent creation.

**Files:**

def has_active_position_for_symbol(self, symbol: str) -> bool:
    """Check if there's a currently open position for this symbol."""
    row = self._conn.execute(
        "SELECT 1 FROM intents WHERE symbol = :symbol AND status = 'opened' LIMIT 1",
        {"symbol": symbol},
    ).fetchone()
    return row is not None

def count_same_direction_today(
    self, symbol: str, side: str, trade_date: str,
) -> int:
    """Count intents that reached execution for this symbol+direction today.

    Counts opened + closed intents (any that got past the 'executing' stage).
    """
    row = self._conn.execute(
        """SELECT COUNT(*) as cnt FROM intents
           WHERE symbol = :symbol AND trade_date = :td
             AND suggested_side = :side
             AND status IN ('opened', 'closed', 'rejected', 'failed')""",
        {"symbol": symbol, "td": trade_date, "side": side},
    ).fetchone()
    return row["cnt"] if row else 0
```

## Task 3: LLM Output Structured Risk Fields (P2.7)

**Problem:** The LLM risk report contains structured advice (avoid zones, trigger zones, invalidation levels) buried in free text. The system cannot programmatically use this information for entry gating.

**Root cause:** `AgentDecision` and `TradeIntent` have no structured fields for risk metadata. Everything goes into `risk_report` as a blob.

**Fix approach:**
1. Add a `RiskMeta` Pydantic model with fields: `entry_style`, `avoid_zone`, `trigger_zone`, `invalid_if`, `max_same_day_attempts`.
2. Add `risk_meta` field to `AgentDecision` class.
3. Add regex-based extraction in `agent_bridge.py` to parse structured fields from risk_report text.
4. The extraction is best-effort — if parsing fails, all fields default to None/empty. No execution blocking based on these fields in this PR (that's a future P3).

**Files:**
- Modify: `src/decision/agent_bridge.py` (add `RiskMeta`, extraction logic, populate in `AgentDecision`)

### Step 2: Implement RiskMeta and extraction

Add to `src/decision/agent_bridge.py`:

import re
from pydantic import BaseModel, Field

class RiskMeta(BaseModel):
    """Structured risk metadata extracted from LLM risk report."""
    entry_style: str | None = Field(default=None, description="e.g. breakout, pullback, momentum")
    avoid_zone: str | None = Field(default=None, description="Price range to avoid")
    trigger_zone: str | None = Field(default=None, description="Price range that triggers entry")
    invalid_if: str | None = Field(default=None, description="Condition that invalidates the trade")
    max_same_day_attempts: int | None = Field(default=None, description="LLM-suggested max retries")

_RISK_META_PATTERNS: dict[str, re.Pattern[str]] = {
    "entry_style": re.compile(r"ENTRY\s+STYLE\s*:\s*(.+)", re.IGNORECASE),
    "avoid_zone": re.compile(r"AVOID\s+ZONE\s*:\s*(.+)", re.IGNORECASE),
    "trigger_zone": re.compile(r"TRIGGER\s+ZONE\s*:\s*(.+)", re.IGNORECASE),
    "invalid_if": re.compile(r"INVALID\s+IF\s*:\s*(.+)", re.IGNORECASE),
    "max_same_day_attempts": re.compile(r"MAX\s+SAME\s+DAY\s+ATTEMPTS\s*:\s*(\d+)", re.IGNORECASE),
}

def extract_risk_meta(risk_report: str) -> RiskMeta:
    """Extract structured risk fields from LLM risk report text.

    Best-effort parsing — returns default RiskMeta if no fields found.
    """
    fields: dict[str, str | int | None] = {}
    for field_name, pattern in _RISK_META_PATTERNS.items():
        match = pattern.search(risk_report)
        if match:
            value = match.group(1).strip()
            if field_name == "max_same_day_attempts":
                fields[field_name] = int(value)
            else:
                fields[field_name] = value
    return RiskMeta(**fields)
```
