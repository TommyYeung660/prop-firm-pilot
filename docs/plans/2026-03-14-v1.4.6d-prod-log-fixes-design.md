# v1.4.6d Prod Log Fixes Design

**Version Target:** `v1.4.6d+`

**Goal:** 修復 `prod_logs_20260314_v1.4.6d/` 暴露的三個問題：週末停市期間仍消耗 LLM / tactical 資源、`NZDUSD` tactical exit 因 broker 精度驗證失敗而無法穩定落地、以及 market-closed 期間仍有少量 `MarketDataHub` REST fallback。

**Scope:** `prop-firm-pilot` scheduler / tactical exit / MatchTrader precision handling；不調整 compliance 規則，不重寫 market-data architecture。

---

## 1. 問題摘要

從 `prod_logs_20260314_v1.4.6d/` 可確認三條具體故障鏈：

1. `2026-03-14 06:00 UTC` 之後，`Execution loop` 與 `LLM worker` 已進入 `market closed` sleep，但 `position monitor` 仍繼續執行 open-position management。
2. `NZDUSD` 倉位 `W5765145699195102` 在多次 `modify_position()` 後，broker 已接受修改，但 `verify_sl_tp()` 因 expected / actual 末位小數精度不一致而回報 mismatch。
3. 週末期間 tactical cycle 仍會拉 `1m/5m/1h` bars，進而觸發 `MarketDataHub: REST fallback for NZDUSD ...` 等 stale fallback。

這三個症狀不是完全獨立：

- `position_monitor` 的 market-closed gate 缺口，會同時導致 tactical exit、market-data fetch、以及潛在 LLM re-evaluation 持續運作。
- broker precision 驗證過嚴，會讓已成功送達的 SL/TP 修改被誤判成失敗，導致 tactical meta 不更新，下一輪再次重送。
- 現有 tactical exit 幾乎只對「獲利後保護」積極，對「初始風險階段已明顯失敗的倉位」缺少 deterministic 提早退出規則。

---

## 2. 設計目標

### 2.1 Functional Goals

- 市場停市時，`position monitor` 不再執行 tactical exit、LLM re-eval、或任何非必要 market-data fetch。
- tactical exit 寫入 broker 後，SL/TP 驗證以 broker precision 為準，不再把已成功的修改誤判為 `verify_failed`。
- 對仍處於 `INITIAL_RISK` 的倉位，新增 deterministic defensive exit，讓明確失敗的結構可在硬 SL 前提早退出。

### 2.2 Risk Goals

- 不改變 compliance math 或 drawdown safety margin。
- 不把 LLM 引入新的 tactical defensive exit；避免額外 token 成本與不可預測性。
- defensive exit 必須保守，避免系統退化成過度敏感的噪音停損器。

### 2.3 Engineering Goals

- 維持 `Scheduler` 為 orchestration 層，不把 rule logic 混進 scheduler。
- 優先用 regression tests 鎖定 root cause，再做最小實作。
- 讓失敗原因可從 log / journal 清楚分辨：closed-market skip、precision-normalized success、defensive exit trigger。

---

## 3. Non-Goals

- 不重構 `MarketDataHub` provider 選擇或 websocket reconnect 策略。
- 不重寫 tactical state machine 成全新多狀態架構。
- 不引入新的線上優化器、reinforcement learning、或 portfolio-level exit policy。
- 不調整 prop-firm compliance 規則或資金風險參數。

---

## 4. 設計

### 4.1 Closed-Market Hard Gate For Position Monitor

目前 `Scheduler._position_monitor_loop()` 即使在 market closed 後，仍會：

- 讀取 open positions
- 執行 `_run_tactical_exit_cycle()`
- 執行 `_reevaluate_open_positions()` exception path
- 間接拉取 `MarketDataHub.get_quote()/get_bars()`

設計上，`market closed` 必須成為 `position_monitor` 的硬閘門：

- 每輪開始先做 market-hours check
- 若市場關閉，只保留必要的 weekend force-close 流程與 loop sleep
- 直接跳過：
  - broker open-position polling
  - tactical exit evaluation
  - LLM re-evaluation
  - tactical market-data fetch

**Design implication:**

- 週末不再消耗 tactical write budget
- 週末不再因 position management 拉 stale bars
- 週末不再走到 LLM exception review 路徑

### 4.2 Tactical Exit Defensive Loss Rule

現有 tactical exit 對以下情境處理不足：

- 倉位仍在 `INITIAL_RISK`
- 尚未達 breakeven / profit-protection 閾值
- 但 5m / 1h 結構已明顯對持倉不利

這使得像昨晚 `NZDUSD` 那種最終 `sl_hit` 的單，幾乎只能等硬 SL。

本次不新增大 state，而是在既有 state machine 上加入一條保守的 deterministic defensive rule：

- 觸發位置：`INITIAL_RISK`
- 優先序：高於一般 `HOLD`，但仍受明確條件限制
- 預期 action：`EXIT_NOW`
- 預期 reason：`initial_risk_structure_failure`

候選條件設計：

- `unrealized_r` 低於新的 defensive 閾值
- `ema_aligned is False`
- `adverse_rsi is True`
- `opposing_candle_strong is True`

規則採保守交集，不用寬鬆 OR 條件，避免把一般 pullback 當成結構失敗。

新增 config 項目：

- `defensive_exit_loss_r`
- `defensive_exit_require_strong_candle`

這樣可讓策略行為保持 deterministic、低 token 成本、且可測試。

### 4.3 Broker Precision Normalization

`NZDUSD` log 顯示：

- expected `TP=0.5664437344099075`
- actual `TP=0.56644`

這不是 broker 拒絕，而是 broker 依 instrument precision 正規化後回寫。

因此 SL/TP 修改流程需要兩層 precision normalization：

1. **Write path normalization**
   - 在 `modify_position()` 送單前，先依 instrument `price_precision` round `sl` / `tp`
   - tactical exit meta 儲存 normalized 值，避免下一輪再以高精度值比較

2. **Read-back verification normalization**
   - `verify_sl_tp()` 比較前，先把 expected / actual 都 normalize 到相同 precision
   - 不再使用與 instrument 無關的固定 `1e-6` tolerance 作為主判準

這會把「broker 成功、scheduler 誤判失敗」修正為真正的 success path。

### 4.4 Data Flow Changes

修正後流程如下：

1. `position_monitor` 進入新一輪
2. 若 market closed：
   - skip position polling
   - skip tactical exit
   - skip re-eval
   - loop sleep
3. 若 market open：
   - tactical exit 取得 market data
   - rule engine 決定 `HOLD / TRAIL_SL / REPRICE_TP / EXIT_NOW`
   - 寫 broker 前先 normalize SL/TP
   - broker 回讀值再 normalize 後驗證
   - 驗證成功才更新 tactical meta

## 5. 測試策略

### 5.1 Scheduler Regression

在 `tests/test_scheduler.py` 新增 coverage：

- market closed 時，`_position_monitor_loop()` 不會呼叫：
  - `get_open_positions()`
  - `_run_tactical_exit_cycle()`
  - `_reevaluate_open_positions()`

### 5.2 Tactical Exit Regression

在 `tests/test_tactical_exit_rules.py` / `tests/test_tactical_exit_manager.py` 新增 coverage：

- `INITIAL_RISK` + 明確反向結構時觸發 defensive exit
- 資料不足或訊號不完整時不觸發 defensive exit
- defensive exit 不依賴 LLM

### 5.3 Execution Precision Regression

在 `tests/test_tactical_exit_execution.py` 與 `tests/test_matchtrader_client.py` 新增 coverage：

- 高精度 SL/TP 送 broker 後，5 位小數回讀仍視為 verify success
- verify success 後 tactical meta 會更新
- normalized equality 時不再重複產生 `verify_failed`

### 5.4 Focused Verification

預期至少跑以下測試：

- `uv run pytest tests/test_scheduler.py -q`
- `uv run pytest tests/test_tactical_exit_rules.py tests/test_tactical_exit_manager.py tests/test_tactical_exit_execution.py -q`
- `uv run pytest tests/test_matchtrader_client.py tests/data/test_market_data_hub.py -q`

---

## 6. 驗收標準

- `market closed` 期間，`position monitor` 不再觸發 tactical exit、LLM re-eval、或 tactical market-data fetch。
- `NZDUSD` 類似 broker precision 裁切情境下，SL/TP modify 可通過 verify 並正確持久化 meta。
- 新 defensive exit 規則可在初始風險階段攔下明確壞結構倉位，但不會對一般小回檔誤觸。
- targeted test suite 維持綠燈，且無新增 lint 問題。
