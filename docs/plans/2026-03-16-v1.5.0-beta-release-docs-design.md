# v1.5.0_beta Cross-Repo Release Docs Design

> **Date:** `2026-03-16`
> **Scope:** `prop-firm-pilot/docs/`
> **Status:** Approved for implementation in-session

## Goal

為 `v1.5.0_beta` 建立兩份正式文件：

- `docs/PropFirmPilot_v1.5.0_beta_Deployment_Manual.md`
- `docs/PropFirmPilot_v1.5.0_beta_Acceptance_Baseline.md`

兩份文件都放在 `prop-firm-pilot/docs/`，但採跨 repo 視角，覆蓋：

- 上游 `qlib_market_scanner`
- 下游 `prop-firm-pilot`
- 兩者之間的 scanner contract、artifact freeze 與 beta 驗收邊界

## Why This Exists

`v1.5.0_beta` 不是單純的版本號提升，也不是 FX runtime cadence 從 `1d` 切到 `1h` 的策略翻轉。這次 beta 的核心是：

- `qlib_market_scanner` 已完成 FX cadence research，並把 canonical FX cadence 凍結為 `1d`
- `prop-firm-pilot` 已正式吸收 scanner bundle contract、version metadata persistence 與 ingestion gate
- 兩個 repo 都已 merge 到 `main`，版本都已 bump 到 `1.5.0_beta`

因此文件必須明確把「部署」與「驗收」拆開：

- 部署手冊回答「怎麼正確部署與 smoke」
- 驗收基線回答「什麼算 beta 可接受、哪些失敗屬於 blocker」

## Design Decisions

### 1. File split

使用兩份文件而不是一份綜合手冊：

- `Deployment Manual` 面向 operator / release owner
- `Acceptance Baseline` 面向 approver / reviewer

### 2. Cross-repo framing

文件主體用 cross-repo release framing，而不是只從 `prop-firm-pilot` 單 repo 寫法出發。原因是這次 beta 的核心價值是上游 research-governed contract 與下游 runtime ingestion gate 的同步落地。

### 3. Evidence discipline

文件只能引用已知已成立的事實：

- `prop-firm-pilot main` 目前基線為 `f7cf416`
- `qlib_market_scanner main` 目前基線為 `0d12fc4`
- 兩個 repo 的 `display_version` 都是 `1.5.0_beta`
- `prop-firm-pilot` 接受 `v1.5.0` 與 `v1.5.0_beta`
- `qlib_market_scanner` canonical FX cadence 為 `1d`

不補寫不存在的 stable / live evidence，也不把 targeted verification 誇大成 full production certification。

## Planned Structure

### Deployment Manual

1. 文件目的與版本邊界
2. 本次 beta 的跨 repo 定義
3. 部署前置條件
4. 應凍結的 release 輸入物
5. 建議部署順序
6. `qlib_market_scanner` 部署步驟
7. `prop-firm-pilot` 部署步驟
8. 部署後 smoke checks
9. 常見失敗模式與處置
10. 回滾原則
11. Beta 驗證窗口要求

### Acceptance Baseline

1. 文件目的與適用範圍
2. 驗收原則
3. Blocker 定義
4. Baseline A: 版本與分支一致性
5. Baseline B: upstream artifact freeze
6. Baseline C: downstream scanner contract 相容性
7. Baseline D: targeted verification evidence
8. Baseline E: runtime / operator smoke evidence
9. Baseline F: 文件對齊
10. 驗收輸出物清單
11. 最終判定格式

## Non-Goals

- 不建立 stable GA 部署手冊
- 不重寫 `ops_runbook.md`
- 不重新定義 FX cadence research 結論
- 不把尚未完成的 multi-day market-open validation 寫成已完成
