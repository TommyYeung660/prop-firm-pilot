# v1.4.1 P0 Memory Identity Design

## 背景

v1.4.0 production incident 顯示 `MemoryJournal` 的 decision block 與 `Trade Result` block 缺少 shared identity。
目前 `log_decision()` 與 `append_trade_result()` 都是 append-only，結果永遠被追加到「當前日期檔尾」。
當 trade 在不同日期平倉，或同日有多筆不同 symbol decision 時，Markdown 記錄會自然錯配。

## 目標

將 `MemoryJournal` 的平倉結果寫入從「today file append」改為「intent-anchored append」：

- decision block 以 `intent_id` 作為 anchor
- append result 時以 `intent_id` 找到原 decision 所在檔案
- 同時在同一個 decision block 內驗證 `symbol`
- 若找不到 anchor 或 symbol mismatch，拒絕寫入結果

## 設計

### 1. Identity Anchor

`Scheduler` 已在 `log_decision()` context 中寫入 `intent_id`。
`MemoryJournal` 新增：

- `_decision_files: dict[str, Path]`：記錄本 process 內已知的 `intent_id -> file_path`
- `_find_file_for_intent()`：當 process 內無 cache 時，掃描 `MEMORY/*.md`，尋找包含該 `intent_id` decision block 的檔案
- `_block_matches_symbol()`：驗證該 block 內的 `Symbol` 是否與 append result 的 `symbol` 相同

### 2. Append Rule

`append_trade_result()` 改為接收：

- `intent_id`
- `position_id`
- `symbol`
- `pnl`
- `reason`

行為改為：

1. 先 resolve `intent_id` 對應的 decision file
2. 驗證同一 block 的 symbol 一致
3. 將 result block append 到該檔案
4. result block 額外寫入 `Intent ID`、`Position ID`
5. 若 anchor 不存在或 mismatch，log warning 並拒寫

### 3. Scope

本次只修 `prop-firm-pilot` 內部的 Markdown journal identity。
不變更 TradingAgents lesson schema，也不變更 reflection payload 寫入行為。

## 驗收標準

- 跨日平倉結果會回寫到原 decision file，而不是當日檔案
- symbol mismatch 不會寫入錯誤結果
- scheduler 平倉時會把 `intent_id + position_id` 傳給 journal
